FPL model — weekly refresh
==========================

Do this after the last gameweek has finished (FPL has logged minutes and points)
and before you pick the next deadline. Live season is 2026-27.

As-of GW T means: use only GW 1 … T−1, plus fixtures already known, to score the
next 5 gameweeks. `fpl-model update` sets T from FPL (current unfinished GW).
Example: after GW2 is done, T is usually 3.


When each source updates (typical PL weekend)
---------------------------------------------
None of these publish a hard SLA; treat the times as “usually ready by”.

  FPL API (live ingest)
    - Points / minutes / BPS: minutes after each FT.
    - Bonus: ~2 hours after each match (can slip).
    - GW “done” for scoring: after the last FT of the GW + bonus locked
      (Sunday night, or Monday night if there is a late game).
    - Prices: ~1–2 hours after the day’s last relevant kickoff window.
    - News / chance_of_playing / ownership: continuous; refresh again before
      the next deadline.
    - is_current flips to the next GW once FPL marks the old one finished.

  Understat
    - Shot/xG during or soon after matches (minutes → a couple of hours).
    - Safe for weekly refresh: last FT of the GW + a few hours, or next morning.
    - If a late kickoff looks missing, rerun Understat next morning.

  FBref (manual HTML — Cloudflare blocks auto-fetch)
    - Standard stats: often same day → next morning.
    - Defense / possession / keepersadv (PSxG): hours → a day; Opta columns
      can stay blank if you save too early.
    - Best: Mon or Tue once tables show real numbers.

  Vaastav GitHub archive
    - Historical only (not for live weekly scoring). Pushed when the maintainer
      scrapes — do not rely on it for the current GW.

Suggested cadence
  1) After last FT + ~2h (bonus settled): optional quick
       fpl-model update --skip-fbref
     for FPL + Understat only.
  2) Mon/Tue: save FBref HTML (section 1), then full
       fpl-model update
  3) Before next deadline: one more update for news / prices / lineups
     (FBref skip is fine if files are already current).


0. Open a terminal
-----------------
cd /Users/thomas/FPL-Model
source .venv/bin/activate


1. Download FBref HTML (browser — Cloudflare blocks auto-fetch)
---------------------------------------------------------------
Prefer Mon/Tue after the GW (see “When each source updates” above).

Save each page as “Webpage, Complete” or “HTML only” into:

  data/raw/fbref/2026-27/

Wait until the tables show real numbers (not blank Opta cells), then save.

  stats.html
  https://fbref.com/en/comps/9/stats/Premier-League-Stats
  (player playing time / standard stats)

  defense.html
  https://fbref.com/en/comps/9/defense/Premier-League-Stats

  keepersadv.html
  https://fbref.com/en/comps/9/keepersadv/Premier-League-Stats
  Check that PSxG and PSxG+/- have numbers for keepers, not empty cells.

  possession.html
  https://fbref.com/en/comps/9/possession/Premier-League-Stats
  Check that Att 3rd / Def 3rd have numbers. Possession % alone is a fallback.

If the browser names the files like
“Premier League Goalkeeper Stats _ FBref.com.html”, leave them in Downloads.
`fpl-model update` (and `fpl-model fbref`) copy the newest matching files into
data/raw/fbref/2026-27/. Or copy/rename by hand:

  cp ~/Downloads/Premier\ League\ Player\ Stats\ _\ FBref.com.html \
    data/raw/fbref/2026-27/stats.html
  cp ~/Downloads/Premier\ League\ Defensive\ Action\ Stats\ _\ FBref.com.html \
    data/raw/fbref/2026-27/defense.html
  cp ~/Downloads/Premier\ League\ Goalkeeper\ Stats\ _\ FBref.com.html \
    data/raw/fbref/2026-27/keepersadv.html
  cp ~/Downloads/Premier\ League\ Possession\ Stats\ _\ FBref.com.html \
    data/raw/fbref/2026-27/possession.html


2. Refresh FPL + Understat + FBref, then score
---------------------------------------------
Save the four HTML files first (Downloads is fine), then one command (live FPL API, Understat,
FBref from those files, features, score). Fixtures with a score or a past kickoff are ingested
even if FPL still has finished=false. Last week’s scores are archived so calibration can run
after the wipe.

  fpl-model update

Auto-download from FBref usually fails (Cloudflare). That is fine: update
still parses the HTML you saved. It prints “fbref mapped N FPL players” and
something like “live FPL 2026-27; scoring as-of GW3 …”. Note the as-of number.

If you already know T (e.g. 3) you can do the same steps by hand:

  fpl-model ingest --season 2026-27 --source live --force
  fpl-model fbref --season 2026-27
  fpl-model features --season 2026-27 --as-of 3
  fpl-model score --season 2026-27 --as-of 3

Do not use last week’s as-of. If you score GW2 after GW2 has finished, you are
leaking that week’s results into the pick for GW3.


3. Sanity-check
--------------
  fpl-model card --season 2026-27 --as-of 3 --name Haaland

You want a printed card with Overall / xPts / action, not “no scores found”.

If FBref said PSxG cells were empty, keepers are still using xGC−GA, and team
tilt is possession % rather than Att 3rd. Re-save keepersadv + possession and
rerun:

  fpl-model fbref --season 2026-27
  fpl-model features --season 2026-27 --as-of 3
  fpl-model score --season 2026-27 --as-of 3


4. Open the UI
---------------
If it is already running, refresh the browser (scores are in SQLite).

If not:

  fpl-model ui --port 8766

Then open http://127.0.0.1:8766

If the UI looks stuck on an old build, stop the old process and start it again
on the same port. Hard-refresh (Cmd-Shift-R) after JS changes.


5. Do not loosen Understat matching
------------------------------------
Unmatched players stay unmatched. They get FPL-proxy xG, a “No Understat map”
badge, and a weaker Underlying score. Do not add fuzzy aliases or bulk-edit
config/player_aliases.yaml unless you are sure of the identity.

  fpl-model id-map --season 2026-27 --export-only

Review the CSV. Only add an alias when the names are the same person.


6. Calibrate after a GW is in the book
---------------------------------------
Uses stored scores (does not overwrite). As-of T’s xPts-next vs actual points
in GW T. For early-season rank quality on a prior season:

  fpl-model calibrate --season 2026-27 --as-of 2
  fpl-model early-check --season 2025-26

Calibration is stored in the DB (and shown on the Fixtures tab). `update` archives
scores before wiping, then calibrates the previous GW from that archive once
official points are in. On My team, Apply bench boost / Apply triple captain
adds bench xPts or a third captain multiplier on the GW XI.

If you already rescored as-of 2 after GW2 finished, that calibration leaks.
Use a historical season, or scores you saved before that GW’s results.


Optional
--------
Understat id mismatches (new signings / spelling): only when you are sure.

  fpl-model id-map --season 2026-27 --export-only
  fpl-model id-map --season 2026-27
  fpl-model features --season 2026-27 --as-of 3
  fpl-model score --season 2026-27 --as-of 3

Do not ingest 2025-26 into the live run or pool gameweeks across seasons.


Optional: import your FPL squad in the UI (My team → FPL team ID from
fantasy.premierleague.com/entry/YOUR_ID/). Public picks can be hidden until
the deadline — if import fails, wait until the current GW starts, or save
the £100m XI as your team.
